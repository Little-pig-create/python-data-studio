# 统一应用与角色鉴权设计

Python Data Studio 采用一个前端应用和一个登录入口，但按用户角色展示不同工作台。统一前端不等于共享全部权限：身份、角色、数据范围和每一次写操作都必须由服务端校验。

## 角色与页面

| 路由 | 学生 | 教师 | 学校管理员 |
|---|---:|---:|---:|
| `/course/:chapterId` | 学习 | 课程预览 | 禁止 |
| `/progress` | 允许 | 禁止 | 禁止 |
| `/datasets` | 允许 | 允许 | 禁止 |
| `/practice` | 允许 | 练习预览 | 禁止 |
| `/training` | 允许 | 禁止 | 禁止 |
| `/teaching` | 禁止 | 允许 | 禁止 |
| `/school-admin` | 禁止 | 禁止 | 允许 |

未登录访问受保护页面会跳转到 `/login`，角色不符会进入 `/forbidden`。未知路由根据当前角色回到各自首页。

## 统一认证接口

默认前缀：`/api/auth/v1`

- `GET /session`：返回当前会话和最小用户资料；
- `POST /login`：账号、密码登录；
- `POST /logout`：注销并使服务端会话失效。

推荐使用 Secure、HttpOnly、SameSite Cookie，前端请求设置 `credentials: include`。角色只能来自服务端会话，生产登录页不允许由用户选择角色。涉及 Cookie 的写接口还需使用合适的 CSRF 防护。

环境变量：

- `VITE_AUTH_API_ENABLED=true`
- `VITE_AUTH_API_BASE_URL=/api/auth/v1`
- `VITE_AUTH_DEMO_MODE=true`：只允许本地开发显式启用，生产构建不得启用。

开发模式提供学生、教师、管理员演示账号，只把最小用户资料放入 `sessionStorage`，不保存密码或真实令牌。

## 业务服务边界

### 学生服务 `/api/student/v1`

获取本人资料和任务、创建尝试、提交 Notebook、同步本人进度。服务端必须从会话识别学生，不接受前端指定任意学号。

### 教师服务 `/api/teacher/v1`

创建和发布实训任务、读取本人任课班级的提交、评阅以及班级汇总。服务端必须同时检查教师角色、任课关系和班级范围。

### 学校管理服务 `/api/admin/v1`

批量建号、班级维护、账号冻结、密码重置和角色分配。所有写操作记录审计日志。批量导入中的初始密码只在请求生命周期中使用，由服务端哈希；前端不保存、不回显已有密码。

## 本地学习数据隔离

学习进度、章节笔记和最近学习记录按用户 ID 保存：

`python-data-studio:learning:{userId}`

同一浏览器切换账号时会激活对应存储，避免机房电脑上不同学生共享本地记录。上线后仍应以服务端进度为权威来源，并处理离线同步冲突。

## 上线前检查

1. 关闭演示模式并接入真实会话接口；
2. 服务端为所有 API 配置角色和资源范围校验；
3. 验证 Cookie、CSRF、会话过期和注销失效；
4. 为批量建号、评阅、角色变更写审计日志；
5. 验证学生 A 无法读取学生 B 的任务、提交与进度；
6. 验证教师只能访问任课班级；
7. 验证管理员页面不能直接读取学生 Notebook 内容，除非另有明确授权。
