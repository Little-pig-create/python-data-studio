# 统一应用与角色鉴权设计

> **当前课程状态（2026-08-02）**：学生学习主路径为章节学习和模块末大作业。`/practice`、`/training` 及 assignments/tasks 相关权限属于未来扩展或兼容接口，不能重新引入已取消的章节作业和独立实训主路径。

Python Data Studio 采用一个前端应用和一个登录入口，但按用户角色展示不同工作台。统一前端不等于共享全部权限：身份、角色、数据范围和每一次写操作都必须由服务端校验。

## 角色与页面

| 路由 | 学生 | 教师 | 学校管理员 |
|---|---:|---:|---:|
| `/course/:chapterId` | 学习 | 课程预览 | 禁止 |
| `/progress` | 允许 | 禁止 | 禁止 |
| `/datasets` | 允许 | 允许 | 禁止 |
| `/practice` | 允许 | 练习预览 | 禁止 |
| `/training` | 允许 | 禁止 | 禁止 |
| `/teaching` | 禁止 | 允许 | 禁止 |
| `/school-admin` | 禁止 | 禁止 | 允许 |

未登录访问受保护页面会跳转到 `/login`，角色不符会进入 `/forbidden`。未知路由根据当前角色回到各自首页。

## 统一认证接口

默认前缀：`/api/auth/v1`

- `GET /session`：返回当前会话和最小用户资料；
- `POST /login`：账号、密码登录；
- `POST /logout`：注销并使服务端会话失效。

推荐使用 Secure、HttpOnly、SameSite Cookie，前端请求设置 `credentials: include`。角色只能来自服务端会话，生产登录页不允许由用户选择角色。涉及 Cookie 的写接口还需使用合适的 CSRF 防护。

环境变量（前端）：

- `VITE_AUTH_API_ENABLED=true`
- `VITE_AUTH_API_BASE_URL=/api/auth/v1`
- `VITE_AUTH_DEMO_MODE=true`：只允许本地开发显式启用，生产构建不得启用。

开发模式提供学生、教师、管理员演示账号，只把最小用户资料放入 `sessionStorage`，不保存密码或真实令牌。

## 服务端实现现状（server/，Rust axum）

`server/` 是独立认证服务（默认 `127.0.0.1:8787`），自 v0.2.0 起具备生产化基础能力：

| 能力 | 实现 |
|---|---|
| 密码存储 | argon2id 哈希（随机盐，`argon2` crate），存储中不出现任何明文密码 |
| 持久化 | 账号/会话/验证码/CDKey 写时保存到 JSON 文件（`PDS_DATA_DIR`，默认 `server-data/`），重启不丢失 |
| 会话过期 | 默认 24 小时 TTL（`PDS_SESSION_TTL_HOURS`），读取时惰性清理过期会话 |
| 登录保护 | 每账号连续失败 5 次（`PDS_LOGIN_MAX_ATTEMPTS`）锁定 10 分钟（`PDS_LOGIN_LOCK_MINUTES`） |
| 验证码 | 只存储 argon2id 哈希；默认不返回明文，仅当显式设置 `PDS_DEV_RETURN_CODE=true` 时开发环境可见 |
| 种子账号 | 首次启动创建三个演示账号（`AUTH_ADMIN_PASSWORD` 等环境变量覆盖默认密码），`PDS_SEED_DEFAULT_USERS=false` 可关闭 |

仍待生产化（不阻塞本地/教学部署）：

- 真实邮件发送适配器（当前验证码哈希存储，传输需接入 SMTP/短信服务）；
- 数据库存储与账号唯一约束（当前为 JSON 文件）；
- 审计日志与 CSRF 防护（写接口使用 HttpOnly Cookie，建议加 SameSite=Strict 与 CSRF Token）；
- 服务端学习进度权威存储（当前进度在浏览器本地）。

## 业务服务边界

### 学生服务 `/api/student/v1`

获取本人资料和任务、创建尝试、提交 Notebook、同步本人进度。服务端必须从会话识别学生，不接受前端指定任意学号。

### 教师服务 `/api/teacher/v1`

创建和发布模块大作业或教师扩展任务、读取本人任课班级的提交、评阅以及班级汇总。服务端必须同时检查教师角色、任课关系和班级范围。

### 学校管理服务 `/api/admin/v1`

批量建号、班级维护、账号冻结、密码重置和角色分配。所有写操作记录审计日志。批量导入中的初始密码只在请求生命周期中使用，由服务端哈希；前端不保存、不回显已有密码。

## 本地学习数据隔离

学习进度、章节笔记和最近学习记录按用户 ID 保存：

`python-data-studio:learning:{userId}`

同一浏览器切换账号时会激活对应存储，避免机房电脑上不同学生共享本地记录。上线后仍应以服务端进度为权威来源，并处理离线同步冲突。
