# Notebook 内容审阅与数学推导补充报告

审阅日期：2026-08-17  
审阅口径：以 `public/course/catalog.json` 中应用实际加载的 127 个 Notebook 为准。

## 1. 审阅结论

本轮共审阅 127 个 Notebook、4,799 个 Cell，其中 Markdown Cell 3,144 个、代码 Cell 1,655 个。

全量结构检查结果：

- 127 个目录项均存在对应 Notebook；
- 目录标题与 Notebook 首标题内容一致；
- 所有 Notebook 均包含应用背景或任务合同；
- 所有 Notebook 均包含练习、里程碑或入口验收；
- 没有空代码 Cell；
- 没有保存的错误输出或 traceback；
- 8 个模块大作业均有 3 个分步参考答案 Cell，全部位于学生任务之后；
- 参考答案带 `solution` 与 `teacher-answer` 标签，页面默认收起，不展示普通 Cell 工具栏。

## 2. 本轮发现并解决的问题

### 2.1 原有数学内容只有“结论公式”，教学链条不完整

原版本的数学 Cell 能说明核心口径，但多数只有一个公式，缺少学生理解所需的中间过程。

现已统一升级为：

1. 从应用问题或统计定义出发；
2. 用 2–4 个步骤拆解量的来源；
3. 展示 2–3 个相互衔接的块级公式；
4. 收束为本章可直接计算的公式；
5. 逐项解释符号；
6. 映射到本章 Python API 或参数；
7. 说明公式成立的条件、数据泄漏风险或业务边界。

补充结果：

- 96 个 Notebook 包含数学推导；
- 覆盖 66 类不同数学主题；
- 共加入 209 个块级公式；
- 每个数学 Cell 至少包含 2 个块级公式；
- 96 个数学 Cell 均通过 KaTeX 严格解析，错误数为 0。

### 2.2 模块导学缺少学生动手的入口验收

NumPy、Pandas、Matplotlib、Seaborn、Plotly、机器学习的模块入门原先只有场景、学习地图和演示，学生可以阅读，但无法确认自己是否已经具备进入模块的最低操作能力。

现已为 6 个模块导学分别加入一个轻量入口验收：

- NumPy：库存数组、缺口计算与布尔筛选；
- Pandas：订单 DataFrame、地区分组与排序；
- Matplotlib：一周销售趋势与完整图表语义；
- Seaborn：新老客分布比较与结果解读；
- Plotly：带目标值 Hover 的交互趋势图；
- 机器学习：分层切分、Dummy 基线与测试评估。

每个入口验收均包含应用背景、三项任务、操作提示、验收标准、学生代码骨架和默认隐藏的参考答案。12 个新增代码 Cell 均通过 Python 语法解析。

## 4. 重点章节抽查

### 第 21 章：统计计算与随机抽样

从均值的离差和为 0 出发，推到样本方差，再由 $\operatorname{Var}(\bar X)=\sigma^2/n$ 得到标准误。代码明确对应 `ddof=1`，并区分标准差与标准误。

### 第 31 章：窗口计算与探索性分析

先定义历史窗口，再推导窗口和与移动平均，最后说明预测当期时为什么需要 `shift(1)`，把“不能使用未来数据”落实到公式和代码顺序。

### 第 54 章：核密度图

先从单个单位面积核出发，解释 $1/h$ 的来源，再对所有核求平均得到 KDE，并说明带宽带来的偏差—方差权衡。

### 第 93 章：随机森林

推导链为：单棵树预测 → 多树平均或概率投票 → 展开平均预测的方差 → 得到

$$
\operatorname{Var}(\bar f_B)
=\sigma^2\left(\rho+\frac{1-\rho}{B}\right)
$$

由此解释：增加 `n_estimators` 只能降低有限树数带来的随机波动；`max_features` 和样本随机化的重要作用，是降低树之间的相关性 $\rho$。

### 第 98 章：PCA

从协方差矩阵出发，把主成分写成约束优化 $\max_{\lVert v\rVert=1}v^T\Sigma v$，再通过拉格朗日乘子推到特征方程 $\Sigma v=\lambda v$，最后连接投影与解释方差比。

### 机器学习模块大作业

从阈值产生的误报、漏报和行动量出发，把三者换算成同一成本单位，再求验证集上的最小成本阈值，并加入运营容量约束。测试集只用于评估已锁定方案，避免反复调参造成泄漏。

- 新增 `check:notebook-math` 与 `check:module-intros`，可在构建前检查内容是否缺失或过期。

## 7. 后续建议

当前没有阻断课程使用的 Notebook 内容问题。后续若继续提升，建议优先做两项：

1. 为少数综合练习增加机器可判定的最小验收函数，让学生不仅能看到答案，还能知道自己的输出是否满足合同；
2. 在学习记录中增加“公式理解 / 代码实现 / 业务解释”三维自评，避免学生只运行代码而没有形成指标解释能力。
