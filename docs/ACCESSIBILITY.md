# 无障碍规范

## 1. 标准

目标达到 WCAG 2.2 AA。所有关键任务必须支持键盘和屏幕阅读器。

## 2. 页面结构

应用必须包含：

- `header` 或等价品牌区；
- `nav` 课程导航；
- `main` Notebook 工作区；
- 可跳过导航的 Skip Link；
- 辅助面板使用明确的 region label。

iframe 必须提供动态标题，例如：

```text
第12章 DataFrame基础 Notebook
```

## 3. 键盘

### 应用外壳

| 按键 | 行为 |
|---|---|
| `Tab` / `Shift+Tab` | 顺序移动焦点 |
| `Enter` / `Space` | 激活按钮或树节点 |
| 方向键 | TreeView 和 Tabs 内移动 |
| `Escape` | 关闭当前顶层浮层 |
| `/` | 聚焦课程搜索，编辑器聚焦时不触发 |
| `Ctrl/Cmd+K` | 打开应用命令面板 |

### Notebook

保留 Jupyter 标准键盘模式，不由外层应用截获编辑器快捷键。

外层全局快捷键必须先判断焦点是否位于 iframe 或文本输入。

## 4. 焦点

- 焦点指示使用 `shadow-focus`；
- 焦点与选中状态可以同时存在；
- 不移除浏览器 outline 后不给替代方案；
- Dialog 打开后焦点进入 Dialog；
- Dialog 关闭后焦点返回触发控件；
- 路由切换后不强制把焦点移出 Notebook；
- 移动端 Drawer 关闭后焦点返回目录按钮。

## 5. 对比度

- 正文与背景至少达到 AA；
- 辅助文字不能低于可读对比度；
- 蓝、绿、黄、红状态同时使用图标或文字；
- 禁用状态仍需可辨识；
- 代码语法主题需单独检查关键 token 对比度。

## 6. 语义与名称

- 图标按钮必须有可访问名称；
- Tooltip 不能是唯一名称来源；
- 运行按钮名称随状态变化：
  - 运行当前单元格；
  - 停止当前执行；
- 保存状态使用 `aria-live="polite"`；
- 运行错误摘要使用 polite，致命运行时错误可以使用 assertive；
- 不把纯装饰 React Bits 元素暴露给可访问树。

## 7. TreeView

- 使用 MUI X 自带语义和键盘行为；
- 当前章节使用 `aria-current` 或等价状态；
- 完成状态有可访问文本；
- 搜索过滤后告知结果数量；
- 模块折叠不丢失当前章节信息。

## 8. Data Grid

- 列名明确；
- 数值与文本类型可辨；
- 数据截断时有文字提示；
- 下载按钮有完整名称；
- 图表必须提供文本摘要；
- 不要求用户仅靠拖动完成列操作。

## 9. Notebook 内容

- Markdown 标题保持正确层级；
- 图片应有替代文本或课程说明；
- 表格有表头；
- 链接文字表达目标；
- 代码和输出可选择、复制；
- 错误输出不因颜色主题而不可读；
- Plotly 图表应提供课程文字解释，不能作为唯一信息来源。

## 10. 缩放与重排

- 浏览器缩放到 `200%` 时核心任务可用；
- `320px` CSS 宽度下无页面级横向滚动；
- 工具栏可以内部横向滚动；
- 长中文标题换行后不覆盖按钮；
- 固定元素不遮挡焦点目标。

## 11. 减少动画

遵守系统 `prefers-reduced-motion`，并允许用户在设置中覆盖。设置通过 Zustand 持久化并同步到 Notebook 主题扩展。

## 12. 测试

- axe 自动检查；
- Playwright 键盘流程；
- Windows Narrator 手动检查；
- 高对比度模式检查；
- 200% 缩放检查；
- 减少动画检查；
- 颜色不作为唯一信息检查。
