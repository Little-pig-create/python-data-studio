## 1. 目标与改造结论

本次改造将课程从“每章一个综合练习 + 独立实训入口”调整为“章节学习 + 模块末大作业”的结构。

### 1.1 取消内容

1. 取消独立的“学生实训/我的实训”作为课程学习主路径。
2. 取消每个章节末尾的正式“综合练习、章节作业、练习路径、迁移挑战”作业。
3. 取消把每个章节都视为一个需要提交和评分的作业单元。
4. 不再让学生在多个章节之间重复提交相似的小任务。

### 1.2 保留内容

以下内容可以保留，但不再作为正式作业：

- 代码运行示例；
- 课堂内即时思考；
- 参数修改提示；
- 结果预测问题；
- 单元末自检清单；
- 章节小结和知识速查表。

这些内容的定位是“课堂学习检查”，不产生独立作业记录，也不占用模块大作业的评分名额。

### 1.3 新结构

每个模块采用以下结构：

```text
模块导学
  ↓
章节学习与运行示例
  ↓
章节小结与课堂自检
  ↓
模块知识地图
  ↓
模块大作业说明
  ↓
公开数据集与数据字典
  ↓
模块大作业 Notebook
  ↓
结果提交、评分与反馈
```

模块大作业不嵌入最后教学章节的 Cell，而是在该模块最后一个教学章节之后作为独立课程章节出现。例如：

- Python 基础：第11章之后，独立模块大作业章节；
- NumPy：第16章之后，独立模块大作业章节；
- Pandas：第25章之后，独立模块大作业章节；
- Matplotlib：第36章之后，独立模块大作业章节；
- Seaborn：第55章之后，独立模块大作业章节；
- Plotly：第72章之后，独立模块大作业章节；
- 综合项目：第76章之后，独立模块大作业章节；
- 机器学习：第109章之后，独立模块大作业章节。

当前实施不重新编号现有教学章节，也不改变现有 `chapter-1`～`chapter-109` 的路径和编号；独立大作业使用单独的 `capstone-*` 入口。若未来新增日期与时间普通章节，应先更新课程事实基线，再统一评估后续章节编号。

## 3. Notebook 单章增强标准

每个章节 Notebook 统一采用以下内容结构。

### 3.1 章节开头

1. 本章学习目标；
2. 本章在模块中的位置；
3. 前置知识；
4. 本章完成后应该得到的可见结果；
5. 运行环境与数据说明。

### 3.2 核心概念

每个核心概念至少包含：

- 简洁定义；
- 一个最小示例；
- 一个实际应用场景；
- 一个容易混淆的概念对比；
- 一个常见错误；
- 一个结果解读问题。

### 3.3 代码注释

注释优先解释“为什么这样做”，而不是重复代码表面含义。

建议使用三种注释：

```python
# 1. 步骤注释：当前处于数据读取、清洗、建模还是评估阶段
# 2. 原因注释：解释为什么选择这个函数、参数或处理顺序
# 3. 风险注释：提示缺失值、数据泄漏、维度不匹配等问题
```

### 3.4 结果打印

每个章节至少展示一种明确的运行结果：

- Python：变量值、类型、流程结果、文件输出；
- NumPy：数组、维度、类型、统计结果、性能比较；
- Pandas：表格、字段类型、缺失值、清洗前后规模、聚合结果；
- Matplotlib/Seaborn/Plotly：图表和图表所依赖的统计摘要；
- 机器学习：数据规模、参数、指标、预测样例和错误样本。

### 3.5 可视化

不要求每个 Python 基础章节都绘制统计图，但每章必须有“可观察结果”。

可视化形式可以是：

- 终端文本；
- Markdown 表格；
- 文件目录树；
- 流程图；
- 数组热力图；
- 静态图表；
- 交互式图表；
- 模型诊断图。

### 3.6 结果解释

每个核心示例后必须回答：

1. 输出说明了什么？
2. 哪个结果最值得关注？
3. 如果结果异常，应该检查什么？
4. 该方法有什么限制？

### 3.7 章节结尾

章节结尾不再设置正式作业，统一替换为：

- 本章小结；
- API 速查；
- 课堂自检；
- 一项参数或数据迁移思考；
- 下一章预告。

迁移思考只要求学生在当前 Notebook 中尝试，不产生独立提交记录。

## 4. 模块末大作业的统一流程

### 阶段一：模块学习

学生按章节顺序完成学习，运行示例并完成课堂自检。

### 阶段二：模块复习

最后一章正文结束后增加“模块知识地图”，将本模块主要知识点按任务流程重新组织。

### 阶段三：作业导入

在独立模块大作业章节的开头展示：

- 项目背景；
- 任务目标；
- 数据集来源；
- 数据字典；
- 必做任务；
- 选做任务；
- 交付物；
- 评分标准；
- 开始作业按钮或 Notebook 入口。

### 阶段四：本地数据准备

所有课程作业优先使用本地数据快照，不要求学生运行时访问互联网。

数据准备规则：

1. 下载或导出公开数据集；
2. 固定课程使用版本；
3. 保存到 `datasets/`；
4. 保存来源、许可、下载日期和数据字典；
5. 对大文件提供课程用子集；
6. 记录抽样方法和随机种子；
7. 运行时只读取本地文件；
8. 在 Notebook 中展示数据来源说明。

### 阶段五：完成作业

学生在独立的模块大作业 Notebook 中完成任务。作业 Notebook 与原课程 Notebook 分离，避免覆盖教材内容。

### 阶段六：结果检查

学生完成以下检查：

- 代码从头运行到尾；
- 无隐藏变量依赖；
- 结果与任务目标一致；
- 图表标题和坐标轴完整；
- 结论能够由数据支持；
- 数据源和限制已说明。

### 阶段七：提交与反馈

作业结果可采用两种方式：

- 本地学习：记录模块大作业完成状态；
- 教学服务接入后：提交 Notebook、结果摘要和评分信息。

原有“实训任务”概念不再作为课程内容名称。若以后继续使用服务端提交能力，接口语义应改为“模块大作业提交”。

### 6.8 机器学习：银行营销转化预测与模型解释

- **放置位置**：第109章之后的独立模块大作业章节
- **数据集**：本地 Bank Marketing 数据
- **项目目标**：完成从问题定义到模型保存和批量预测的完整机器学习流程

#### 必做任务

1. 定义营销响应预测目标；
2. 检查类别分布和数据质量；
3. 划分训练集、验证集和测试集；
4. 建立多数类和逻辑回归基线；
5. 使用Pipeline完成预处理；
6. 比较逻辑回归、随机森林和梯度提升模型；
7. 使用交叉验证评估稳定性；
8. 进行一次网格搜索或随机搜索；
9. 输出准确率、精确率、召回率、F1、ROC-AUC和PR-AUC；
10. 绘制混淆矩阵、ROC曲线和PR曲线；
11. 分析错误样本；
12. 解释特征重要性或模型系数；
13. 保存最佳模型；
14. 对新数据进行批量预测；
15. 编写模型卡，说明适用范围和限制。

#### 结果要求

不能只报告准确率。必须说明：

- 哪类错误成本更高；
- 阈值如何影响营销名单规模；
- 训练分数和测试分数是否存在明显差异；
- 模型是否适合直接用于真实业务决策；
- 数据中是否包含可能造成数据泄漏的字段。

## 9. 教学文件质量评估标准

后续将独立生成 Notebook 质量评估报告，不由内容修改过程自行判定“完成”。

### 9.1 结构维度

- 是否有学习目标；
- 是否有前置知识；
- 是否有核心概念；
- 是否有最小、组合和应用示例；
- 是否有章节小结；
- 模块末是否有大作业入口。

### 9.2 教学维度

- 概念是否先于代码；
- 代码是否有必要注释；
- 是否解释参数和原因；
- 是否存在跳步；
- 是否能帮助初学者理解输出；
- 是否有常见错误和限制说明。

### 9.3 结果维度

- 是否有实际运行输出；
- 输出是否能够验证代码目标；
- 是否打印关键中间结果；
- 图表是否完整；
- 图表是否有解释；
- 结果是否可复现。

### 9.4 工程维度

- Notebook是否能从头运行；
- 是否存在隐藏状态；
- 是否依赖外部网络；
- 数据路径是否稳定；
- 是否固定随机种子；
- 是否存在不必要的大输出；
- 是否有数据源和许可说明。

### 9.5 评分等级

| 等级 | 说明 |
|---|---|
| A | 内容完整、流程清晰、可运行、结果可解释、适合直接教学 |
| B | 基本可教学，但有少量注释、输出或解释缺口 |
| C | 能运行但教学链路不完整，需要补充关键内容 |
| D | 存在运行、路径、依赖或结构性问题，不建议直接使用 |

## 3.8 Notebook 单元格顺序标准（新增）

为保证从浅入深，章节 Notebook 统一按以下顺序组织单元格：

1. **章节标题与教学提示**：说明模块位置、学习重点和结果记录要求；
2. **问题导入与学习目标**：先用一个小问题说明为什么学习本章；
3. **前置知识与运行规则**：明确需要掌握的内容、内核状态和执行顺序；
4. **核心概念**：先讲数据结构、语法或对象关系，再进入复杂代码；
5. **方法与函数分步讲解**：每个核心方法使用独立 Markdown 单元格和独立代码单元格，说明作用、参数、返回值、边界和最小示例；
6. **章节示例**：把前面学过的方法组合成一个小流程；
7. **结果解读与可视化**：解释输出、图表或模型指标，不只展示结果；
8. **常见误区与排错**：集中处理类型、顺序、边界、数据泄漏和图表表达问题；
9. **本章小结与课堂检查**：总结知识点，保留课堂自检，不设置章节作业；
10. **模块末大作业**：作为模块最后一章之后的独立课程章节出现。

方法讲解单元格不得把多个方法压缩到一个代码单元格中。学生应能单独运行、修改和解释每一个核心方法的示例。
