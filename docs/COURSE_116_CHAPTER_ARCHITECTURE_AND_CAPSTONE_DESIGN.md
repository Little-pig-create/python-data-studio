## 1. 章节拆分与合并原则

### 1.1 应当拆章的情况

满足以下任一条件时，可以拆成独立章节：

1. 核心对象不同，例如列表与元组；
2. 核心思维不同，例如字典的键值映射与集合的成员关系；
3. 前置知识或学习产出明显不同；
4. 一个章节预计超过70分钟或超过约60个有效教学Cell；
5. 学习者需要分别完成两套独立练习才能证明掌握。

### 1.2 应当合并的情况

以下内容应放在同一章：

1. 同一个对象的不同方法；
2. 同一个任务流程的连续步骤；
3. 只是参数、展示方式或接口层级不同；
4. 适合通过对比理解的相似图表或算法；
5. 拆开后无法形成独立问题、独立案例和独立产出。

### 1.3 方法与章节的关系

方法不等于章节。字符串、列表、Pandas等方法较多的章节，应通过“方法分类速查 + 每个方法独立说明Cell + 每个方法独立代码Cell”完成教学，而不是把每个方法拆成一章。

## 4. 单章Notebook内部架构

每个普通教学章节统一采用以下顺序：

1. 本章标题和学习场景；
2. 在模块中的位置；
3. 前置知识；
4. 可观察学习目标；
5. 本章三级目录；
6. 核心概念和最小示例；
7. 方法分类速查；
8. 每个方法的独立说明Cell；
9. 每个方法的独立代码Cell；
10. 方法之间的对比实验；
11. 常见错误与恢复方式；
12. 一个连续的综合案例；
13. 课堂自检和参数迁移；
14. 本章小结、关键速查和下一章衔接。

### 4.1 方法单元模板

每个方法使用固定结构：

| 内容 | 要求 |
| --- | --- |
| 方法名称 | 显示完整名称和调用形式 |
| 作用 | 用一句话说明解决什么问题 |
| 输入 | 说明重要参数和输入类型 |
| 返回值 | 说明返回新对象、标量还是None |
| 是否修改原对象 | 对可变对象必须明确说明 |
| 最小示例 | 一个独立、可直接运行的代码Cell |
| 输出解释 | 紧邻示例解释结果 |
| 常见错误 | 至少说明一个初学者易错点 |

### 4.2 章节练习边界

普通章节不设置正式提交作业，只保留：

- 运行前预测；
- 补全一处代码；
- 修复一个错误；
- 改变一个参数并比较；
- 一项不需要提交的迁移练习。

正式成果统一放在模块大作业中。

## 5. 模块大作业统一架构

- 核心计算过程；
