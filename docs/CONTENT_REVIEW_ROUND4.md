## 三、设计方案：让 `本章场景` 真正承担职责

**职责划分**（避免与核心概念重复）：

| 环节 | 应回答的问题 | 不应包含 |
| --- | --- | --- |
| **本章场景** | **为什么现在要学它？** 业务触发事件、**本章在项目主线中的位置**、学完能解决什么 | 方法定义、参数细节 |
| **核心概念** | **它是什么？** 定义、要点、直观类比 | 业务故事 |

**改写模板**（以 ch31 窗口计算为例，23 字 → 约 130 字）：

```
## 本章场景

上一章的周报只报了"本月总销售额 86 万"，会上老板追问："最近是不是在往下掉？"
你只能回答"总额还行"——因为一张只有总数的表**看不出趋势**。

要把"最近卖得怎么样"答清楚，需要给每个时间点配上"近几天的均值"，
再看清波动、相关与分布。本章就为周报补上这块能力，
学完后你能在复盘会上直接回答"趋势、波动、异常"三类追问。
```

**关键**：场景引用**业务事件**（周会追问）与**项目主线位置**（上一章只报了总数），
而不是重复"一列长长的销售记录看不出趋势"。
